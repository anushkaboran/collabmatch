# CollabMatch

Find local creators who fit your budget. DubHacks 2026.

A small business describes a campaign in one sentence. Gemini turns it into a brief, MongoDB Atlas narrows the creators, a transparent formula scores them, and an optimizer picks the best **team** of creators that fits the budget. The business invites them in one tap; creators connect Instagram and accept, pass or ask for more.

## Run it

```bash
npm install
cp .env.example .env.local   # optional: works with every value empty
npm run dev                  # http://localhost:3000
```

With no keys the app still runs end to end: in-memory database, keyword parser instead of Gemini, and a sample creator instead of Instagram login. `GET /api/health` shows what's switched on.

## Backend setup (Person A)

### 1. MongoDB Atlas (~15 min)

1. Create a free **M0** cluster at [mongodb.com/atlas](https://www.mongodb.com/atlas).
2. **Database Access** → add a user with read/write. **Network Access** → allow `0.0.0.0/0` (Vercel's IPs change).
3. **Connect → Drivers** → copy the connection string into `MONGODB_URI` (put the user's password in it).
4. Start the app. The first request creates the indexes and loads the 14 sample creators and 3 businesses. `POST /api/seed` (the "Start over" button) resets everything.
5. Check in **Data Explorer**: `collabmatch.collaborations` documents gain `history` entries as statuses change; **Indexes** tab lists the indexes.

### 2. Gemini (~5 min)

1. Get a key at [aistudio.google.com/apikey](https://aistudio.google.com/apikey) → `GEMINI_API_KEY`.
2. `GEMINI_MODEL` defaults to `gemini-2.5-flash`; use any current Flash model.
3. Check: search on the home page → the campaign shows **✦ Generated by Gemini** (instead of "Quick parse"). `POST /api/proposals` returns `"source": "gemini"`.

### 3. Instagram login (~45 min, start early)

1. [developers.facebook.com](https://developers.facebook.com) → create an app → add **Instagram** → **API setup with Instagram login**.
2. Copy the Instagram app ID and secret → `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET`.
3. Add redirect URIs: `http://localhost:3000/api/auth/instagram/callback` and `https://<your-domain>/api/auth/instagram/callback`. Set `INSTAGRAM_REDIRECT_URI` to the one for the environment.
4. Switch your own Instagram accounts to **creator** accounts (free) and add them as **testers** in the app's roles; accept the invite in Instagram. Until Meta reviews the app, only testers can log in.
5. Permissions requested: `instagram_business_basic`, `instagram_business_manage_insights`. Follower count and audience demographics only come back for accounts with 100+ followers; Gemini reads the posts either way.
6. Flow: `/api/auth/instagram` → Instagram → `/api/auth/instagram/callback` → token saved in `oauthTokens` (never sent to the browser) → profile, last 25 posts, audience → Gemini analysis → verified creator → `/creator?creatorId=…`. From an invite link, the creator's profile is claimed and they land back on the invite.

### 4. Deploy on Vercel (~15 min)

1. Import the GitHub repo in Vercel.
2. Add every variable from `.env.example` (MONGODB_URI is **required** on Vercel).
3. Deploy, then add the production callback URL to the Instagram app.
4. Add Person B to the Vercel project for the custom domain.

### 5. VEYZL audit (~1 h, after the core works)

1. Sign in to VEYZL with GitHub and give it access to this repo.
2. Open a pull request that touches the AI code (e.g. a branch with a small change to `src/lib/server/gemini.ts`) and run VEYZL's audit on it.
3. Fix what it flags. `src/lib/server/safety.ts` already covers the likely findings, so compare its report against it:
   - **AI promises:** `checkProposal` rejects a Gemini draft whose dollar amounts differ from the approved fee or that adds perks/terms; we fall back to the template.
   - **Prompt injection:** captions, bios and business notes go to Gemini inside `<untrusted>` markers, and every output is validated against fixed vocabularies.
   - **Sensitive data:** `scrub` redacts tokens and secrets from logs; Gemini failures log only the error message; Instagram tokens live server-side only.
   - **Input limits:** handles, notes, fees and messages are validated and clamped in the routes.
4. Re-run the audit, merge, keep screenshots of the finding, the diff and the clean re-run.

## API

| Method + path | Body / query | Returns |
| --- | --- | --- |
| `POST /api/campaigns/parse` | `{ prompt }` | `{ brief, source }` |
| `POST /api/campaigns` | `{ businessId, prompt, brief, briefSource }` | `Campaign` |
| `GET /api/campaigns?businessId=` | | `Campaign[]` |
| `GET /api/campaigns/[id]` | | `{ campaign, collaborations }` |
| `PATCH /api/campaigns/[id]` | partial brief (budget, tags) | `Campaign` |
| `GET /api/campaigns/[id]/matches` | | `{ matches, teams }` |
| `POST /api/proposals` | `{ campaignId, creatorId }` | `{ proposal, source }` |
| `POST /api/collaborations` | `{ campaignId, invites: [{ creatorId, proposal, offeredFee }] }` | `Collaboration[]` |
| `GET /api/collaborations?campaignId=` or `?creatorId=` | | `CollaborationView[]` |
| `PATCH /api/collaborations/[id]` | `{ status, counterFee?, counterNote? }` | `Collaboration` |
| `GET /api/creators`, `GET/PATCH /api/creators/[id]` | | `Creator` |
| `POST /api/creators/[id]/analyze` | | `Creator` (Gemini re-read) |
| `POST /api/creators/import` | `{ handle, platform, followers, notes }` | `Creator` (unverified, estimated rate) |
| `GET /api/invite/[token]`, `POST /api/invite/[token]/respond` | `{ action, fee?, note? }` | invite view / `Collaboration` |
| `GET /api/auth/instagram`, `GET /api/auth/instagram/callback` | | redirects |
| `POST /api/demo/connect`, `POST /api/seed`, `GET /api/health`, `GET /api/businesses` | | demo helpers |

Errors are `{ error }` with a 4xx/5xx status. Status moves allowed: invited → accepted / declined / countered; countered → accepted (fee becomes the counter) / invited; accepted → in_progress → submitted → completed.

## Code map

- `src/lib/types.ts`: shared contract. `src/lib/engine.ts`: matching formula, team optimizer, keyword parser, templates (shared by server and offline mode).
- `src/lib/server/`: Atlas repository, Gemini, Instagram, safety, services, route wrapper.
- `src/app/api/**`: route handlers. `src/app/**`, `src/components/**`: screens (Person B).
- `src/mocks/`: seed data and the offline browser store (`NEXT_PUBLIC_USE_MOCKS=true`).

Next.js 16.4 (App Router, Cache Components), React 19, TypeScript, Tailwind CSS 4, MongoDB driver 7, `@google/genai` 2. Creator seed data is synthetic.
